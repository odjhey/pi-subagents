# Preset creator acceptance

The authoring skill creates both independent preset packages and individual agent definitions. Validation exercised the packed creator, its generated output, and a real Pi authoring session.

Environment: Pi 0.85.0, Node 24.14.0, the local `odjhey/pi-subagents` v1 checkout, and the configured `openai-codex/gpt-5.6-sol` model for the live authoring run.

## Automated checks

```bash
PI_SUBAGENTS_DIR=/Users/odz/packages/pi-subagents npm test
```

All eight tests passed:

1. The packed creator contains its skill, reference, example, and executable helpers; Pi loads its skill without diagnostics.
2. A relocated creator generates a two-agent preset whose agents and parent skill survive packing and load with the production kernel and Pi loaders.
3. An agents-only package validates without requiring a parent skill.
4. Quoted and multiline descriptions, prompts, empty tool lists, and explicit launch defaults round-trip through production discovery.
5. Invalid specs, unknown fields, duplicate names, and unsafe names fail before creating the output.
6. Existing files, directories, and dangling symlinks remain unchanged when generation is refused.
7. The checker rejects an agent made invalid by a manual `role` frontmatter field.
8. The checker catches omitted packed skills and nonportable absolute skill paths.

The skill-creator frontmatter validator also passes. The creator tarball contains exactly eight files; development tests and this evidence are excluded.

## Real authoring test

Installed the extracted creator package in a disposable Pi project and invoked `/skill:preset-creator` with a natural-language request to create:

- A local documentation-review preset with `docs-fact-checker`, `docs-clarity-reviewer`, and a `docs-review` parent skill.
- A standalone `api-mapper` agent under the disposable project's `.pi/agents` directory.

The request required inspection-only tools, preservation of existing files/settings, all authoring artifacts inside the temporary workspace, and validation against the local kernel. It explicitly excluded running or installing the generated agents.

The author read the contract and example, wrote domain-specific JSON specs, used both scaffold modes, inspected the output, and ran the checker. Independent checks after Pi exited confirmed:

- The generated preset has five packed files, two usable agents, and one usable parent skill.
- The standalone definition loads as `api-mapper`.
- All three generated agents use `read`, `grep`, `find`, and `ls`, fresh context, and no pinned model.
- Existing `keep.txt`, AGENTS.md, and project settings retained their SHA-256 hashes.

The provider run completed in approximately 86 seconds; the run plus independent output checks took approximately 88 seconds. Raw prompts, traces, generated files, specs, and `result.json` remain locally under `/tmp/pi-preset-authoring.2zs3o835/`.

This proves authoring and loadability. The generated documentation-review team was not executed in this test, so its review quality and handoffs are not claimed as verified. Authors should exercise a new team on a representative task before treating it as behaviorally accepted.

## Repository integration

Moved the creator source into `pi-subagents/packages/preset-creator`, retaining its own package manifest and separate installation. Tests now default to the containing kernel checkout, with `PI_SUBAGENTS_DIR` available as an override. The root `test:all` command includes creator tests, and CI checks both package boundaries.

From the repository root:

```bash
npm run typecheck
npm run test:all
```

Typecheck and all 76 tests passed: 55 unit, 10 integration, 3 root package proofs, and 8 creator tests. Packing still produces exactly 17 files for the root kernel and 8 for the creator; creator resources are excluded from the kernel tarball.

The first full run failed the unchanged integration test `never-settling bind cancellation is bounded and restores the child environment`: its 5 ms cleanup budget produced one shutdown call where the assertion expected zero. The isolated test passed in both this checkout and the original v1.0.0 acceptance checkout, and the subsequent full run passed without changes to the lifecycle implementation or test. This remains an intermittent timing-sensitive assertion; the move does not establish that it is fixed.

A disposable Pi project installed `/Users/odz/packages/pi-subagents/packages/preset-creator` using `pi install -l --approve`. A fresh RPC session exposed `skill:preset-creator` through `get_commands`, with no provider calls.
